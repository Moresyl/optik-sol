# Contributing

English | [简体中文](CONTRIBUTING.zh-CN.md)

**Open the playground on a phone before you change any code.** Almost every design decision in this project came from a failure on a real device; a change that looks fine in desktop Chrome can be entirely invalid on a phone.

## Environment

Node ≥ 20, pnpm 10 (the repo pins `packageManager`, so `corepack enable` picks up the right version automatically).

```bash
pnpm install
pnpm dev          # starts the playground; the page header shows a LAN address and QR code
pnpm typecheck
pnpm build
```

CI runs exactly `typecheck` + `build`, plus a check that the build output is non-empty. If it passes locally, it will almost certainly pass in CI.

## One trap you must know: UnoCSS is not a Vite plugin here

`optik-ui` styles are generated by the CLI, not on demand at runtime:

```bash
pnpm --filter optik-ui css     # scans src/**/*.{ts,tsx} → src/generated/uno.css
```

`packages/ui/src/index.ts` inlines that output into the Shadow DOM with `?inline`. **So a newly written class name does not exist until the CSS is regenerated** — there is no error, only silent no-op: write a button with `w-10` and it collapses to content width, which looks like a broken layout.

`pnpm dev` already runs the watcher. But if you run `vite` on its own, or build straight after a fresh checkout, run `css` once first. `src/generated/` is not tracked in version control.

## Hard constraints

Non-negotiable; the reasoning is in [DESIGN.md](DESIGN.md).

- UI copy is **Chinese** throughout, including `aria-label`, `title`, toasts and empty states
- Sizes in **px** only, never rem
- Touch targets ≥ **44 px**, input font size ≥ **16 px** (may shrink for mouse input, never for touch)
- Height uses **`100dvh`**, edges respect `env(safe-area-inset-*)`
- Hooks must be **fully reversible**: pass through to the original method, guard against re-entry, never throw into the host, and restore from the original property descriptor on `destroy()`
- **No DOM references anywhere in the kernel**, and the UI may not bypass `Transport` to reach kernel internals
- Comments explain *why*, not *what*

## Verification

Every button in the playground maps to a **scenario known to break debugging tools**: circular references, 100k-element arrays, getters with side effects, cross-realm objects, non-bubbling resource errors, opaque cross-origin responses.

If your change touches any of the following, confirm it on a real device (or device emulation with touch simulation):

- The copy path, especially the fallback route on **non-secure HTTP origins**
- Long-press text selection (one `preventDefault` in a gesture handler kills it)
- The split threshold (≥ 640 px) and compact layout (`pointer: fine`)
- Safe areas, and the layout after the soft keyboard opens

## Pull requests and bug reports

One PR, one thing. In the description, **explain how things break without the change** — that is more useful than listing what you changed. For UI changes, attach a screenshot or screen recording, preferably from a phone.

Bug reports must include: **device model + OS version, browser or WebView, whether the page is served over HTTPS or HTTP, and the Optik Sol version.** Any one of these missing can make the issue impossible to reproduce.
